# StockFlow

StockFlow — учебный прототип системы автоматизации складского учёта для лабораторных работ Московского Политеха по дисциплине «Автоматизация процессов жизненного цикла программных средств».

Текущий этап: лабораторная работа №2 «Виртуализация». Проект запускается локально или внутри виртуальной машины с установленными Node.js и npm.

## Возможности прототипа

- Главная страница на русском языке с адаптивным интерфейсом.
- Четыре раздела: материалы, поставщики, поступления и остатки.
- Навигация по разделам и демонстрационные данные, заданные в коде страницы.
- Endpoint `GET /api/health` для проверки состояния сервиса.

Данные вымышленные. Прототип не поддерживает редактирование, сохранение и реальный складской учёт. Docker, PostgreSQL, Drizzle, TeamCity, CI/CD и авторизация отложены до следующих лабораторных работ.

## Стек

Next.js 16, React 19, TypeScript, npm, ESLint, App Router. Стили написаны на обычном CSS. Внешние шрифты и сервисы не требуются.

## Требования

Node.js 20.9 или новее и npm. Рекомендуется актуальная LTS-версия Node.js. Точные версии установленных зависимостей зафиксированы в `package-lock.json`.

## Запуск

Установите зависимости из каталога проекта:

```bash
npm install
```

Запустите сервер разработки:

```bash
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

## Проверка и production-сборка

Проверка ESLint (без допуска предупреждений):

```bash
npm run lint
```

Создайте production-сборку:

```bash
npm run build
```

После успешной сборки запустите приложение:

```bash
npm start
```

Сервер доступен по адресу [http://localhost:3000](http://localhost:3000). В Next.js 16 lint выполняется отдельно от сборки; см. [официальную документацию](https://nextjs.org/docs/app/getting-started/installation).

## Проверка состояния

Откройте [http://localhost:3000/api/health](http://localhost:3000/api/health) при работающем сервере. Ответ: HTTP 200, `application/json`:

```json
{"status":"ok","service":"stockflow"}
```

Это проверка доступности приложения. Подключений к базе данных в прототипе нет.

## Переменные окружения

Для запуска переменные окружения не нужны. `.env.example` содержит только комментарии и может служить основой для последующих лабораторных. Настоящие секреты и ключи не следует добавлять в Git. Файлы `.env`, `.env.local`, другие локальные `.env.*`, `node_modules` и `.next` исключены через `.gitignore`; `.env.example` разрешён.
