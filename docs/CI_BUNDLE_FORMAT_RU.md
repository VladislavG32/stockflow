# Передача образов Verify → Publish

Verify собирает образы один раз и выполняет `docker save | gzip -1`.
`scripts/ci/split-bundle.sh` заменяет полный архив следующими файлами:

- `ci-images.tar.gz.part-000000`, `part-000001`, … — до 200 000 000 байт каждый;
- `ci-images.parts.sha256` — упорядоченные SHA-256 всех частей;
- `ci-images.sha256` — SHA-256 **полного** исходного `ci-images.tar.gz`.

Полный архив после успешного разбиения удаляется только из каталога результатов
упаковщика. Образы, контейнеры и volumes не удаляются. Лимит сервера 300 МБ
менять не требуется. Для тестов размер части можно уменьшить переменной
`STOCKFLOW_BUNDLE_PART_BYTES`; увеличить выше 200 000 000 байт нельзя.

Существующие TeamCity rules совместимы без изменения:
`artifacts/* => checks` и `checks/ci-images.* => incoming`.
Snapshot dependency и `sameChain()` оставлены: Publish получает образы именно
соответствующего Verify и не пересобирает их.

`load-bundle.sh` проверяет последовательность имён, количество, наличие и SHA-256
частей, восстанавливает архив во временном каталоге, проверяет полный SHA-256,
gzip и tar **до первого обращения к Docker**. После `docker load` проверяются
revision labels runner и migrator относительно текущего Git HEAD.
Произвольные пути и команды из manifests не исполняются. Старый цельный архив
с `ci-images.sha256` поддерживается; смешанные форматы отвергаются.

Во время разбиения требуется место для полного архива и всех частей (около 2S).
Во время восстановления — для скачанных частей и временного полного архива
(тоже около 2S), плюс место для распаковки образов самим Docker. Временный архив
удаляется при выходе, в том числе при ошибке. Суммарный объём хранения артефактов
практически прежний; разбиение устраняет лимит **одного файла**, а не нехватку диска.
Нужны GNU `split`, `sha256sum`, `tar`, `gzip` и Bash на Linux-агенте.

Finish Build Trigger Publish в `.teamcity/settings.kts` явно имеет
`enabled = false`; ручной Publish сохранён. Само изменение Git не включает
Versioned Settings и не меняет действующие серверные настройки. Импорт DSL,
Publish и Deploy требуют отдельного согласования. Для проверки формата без
Docker daemon: `npm run test:infra` (Docker в тестах подменён).
