## TeamCity: проверено и неизвестно

Отдельного подключённого инструмента TeamCity в сессии нет. Этот адрес — пример, не установленный адрес действующего сервера. **Доступа к действующему TeamCity нет.** Реальный URL, Versioned Settings VCS root, выбранная ветка, история запусков, очередь, наследуемые настройки и credentials неизвестны.

По репозиторию подтверждено:

- Source: GitHub `VladislavG32/stockflow`, `refs/heads/dev`, branchSpec `+:refs/heads/(*)`. Это source root, а не доказательство серверного Versioned Settings root.
- Verify: VCS trigger на все ветки, `stockflow-build-agent`, clean checkout On agent, lint/typecheck/infra/unit/build в контейнере Node 24, затем архив runner/migrator и checksum.
- Publish: тот же Linux build-agent, ветки dev / `<default>` / prod, finish trigger после успешного Verify, snapshot dependency с запретом старта после ошибки и артефакты той же цепочки. Скрипт дополнительно допускает только dev/prod.
- Нужны Password-параметры `env.DOCKERHUB_USER`, `env.DOCKERHUB_TOKEN` только у Publish, токен с правом записи и `env.IMAGE_REPO=<login>/stockflow`. В Git секретов нет, IMAGE_REPO — заглушка `SET_DOCKERHUB_USER/stockflow`. Наличие серверных значений и их работоспособность не подтверждены; секреты не выводились.
- Versioned Settings требуется проверить отдельно. Для сопровождения после PR №1 согласованный источник — dev; `prep/lab4-ci` остаётся исторической контрольной точкой и не обновится из dev автоматически. Проверить текущие доверенные настройки, не разрешать произвольным feature-веткам подменять DSL с секретами.

Если живой сервер соответствует DSL и триггеры включены, merge в dev запустит Verify. После успеха возможен **автоматический Publish**: загрузка архива, теги `dev-<полный SHA>` / `dev-<полный SHA>-migrator`, push/pull Docker Hub и `release.env` с digest. Это публикация, даже без Deploy. Отсутствие секретов может остановить Publish ошибкой, но не является надёжным способом его отключения.

Текущий DSL не содержит Stage/Prod deploy; автоматическое развёртывание из него не следует. Дополнительные серверные/внешние триггеры без доступа исключить нельзя. Никакие сборки TeamCity, Docker push, Deploy или подключения к рабочим стендам в этой задаче не выполнялись.
