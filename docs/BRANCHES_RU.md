## Безопасное продолжение

1. Проверить и согласовать новый PR в dev; слияние выполняется отдельно по решению владельца.
2. Сохранить исторические контрольные версии, прежде чем переносить обновления в будущие этапы.
3. Ветку для фактической ЛР №5 создавать от согласованного dev и переносить нужную подготовку выборочно. Из `feature/labs4-8-preparation` нельзя брать миграции `0001`/`0002` раньше ЛР №8.
4. При переносе UI учитывать конфликты в dashboard, формах, таблицах и validation будущих этапов. Сохранить новые безопасные версии зависимостей; повторить проверки.
5. Ветки `main`, `dev`, `prod`, настройки TeamCity и рабочие VM не изменяются самим фактом создания feature/PR. Push feature может вызвать существующую Verify, если внешний TeamCity уже подключён; Publish в текущем DSL ограничен dev/prod.

Профессиональный порядок в этом учебном репозитории достигается понятным указателем и достоверными контрольными точками. Удаление файлов из новой ветки не отменяет опубликованную историю и не используется для её сокрытия.
