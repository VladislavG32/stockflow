Дата: 18 октября 2026 года. Проверки выполнены локально в Windows, в ветке `feature/lab3-stockflow`. Это не отчёт о запуске на виртуальных машинах.

Для PostgreSQL-проверки использованы отдельные Windows-бинарники PostgreSQL 17.10 из пакета `@embedded-postgres/windows-x64`, установленного вне репозитория во временный каталог. Это настоящий PostgreSQL, не in-memory замена и не SQLite. В проект не добавлена зависимость embedded-postgres. Проверочная БД слушает только `127.0.0.1:55432`; локальное приложение — `127.0.0.1:3001`. Параметры сохранены в игнорируемом `.env`, пароль не выводился. Уникальные QA-записи после проверок удалены; оставлены только явно добавленные учебные примеры DEMO.

Production build в Windows нужно выполнять при остановленном локальном standalone-сервере. Обнаруженная блокировка каталога EBUSY устранена остановкой собственного проверочного процесса, после чего build прошёл. Ни проверка типов, ни lint не отключались.

## Что не удалось проверить в этой среде

- Docker CLI 29.8.0 и Compose 5.5.1 установлены, но Docker Desktop не смог запустить Linux engine. `wsl --status` сообщил, что WSL не установлен. Системные компоненты не устанавливались и настройки виртуализации не менялись.
- Поэтому Dockerfile не проверен реальной сборкой контейнера; старт цепочки db → migrate → app и сохранность **Docker volume** после пересоздания контейнеров остаются для проверки на Ubuntu VM.
- Успешный перезапуск локального PostgreSQL доказывает сохранение данных его файлового кластера, но не заменяет тест Docker volume.
- SSH-доступ к TEST/STAGE/PROD не выполнялся: нет подтверждённого логина и сеанса. Инструкция для этих VM подготовлена, но её выполнение не приписывается автору.
- Полного исходного ТЗ ЛР №1 и старых отчётов в репозитории нет. Сохранены все известные требования исходного прототипа; старые отчёты не редактировались.

## Аудит зависимостей

`npm audit --omit=dev`: 0 уязвимостей в production-зависимостях на момент проверки.

Полный `npm audit` сообщает 9 уязвимостей инструментов разработки: 5 high в цепочке ESLint/fast-glob/micromatch/braces и 4 moderate в цепочке drizzle-kit/@esbuild-kit/esbuild. Обычный `npm audit fix` не устранил их. Предложенный npm вариант `--force` понижает eslint-config-next до 14.x и drizzle-kit до 0.18.x, поэтому не применялся: это несовместимое изменение выбранного стека и миграций, а не исправление приложения. Сообщения не скрыты; ожидается совместимое обновление инструментов. Dev-сервер esbuild для проекта не запускается.

## Что выполнить самостоятельно

Опубликовать feature-ветку, затем пройти `LAB3_STEPS_RU.md` на TEST, STAGE и PROD, собрать контейнеры, проверить работу форм, ready и сохранность volume. Снять собственные скриншоты с адресами VM и зафиксировать фактически проверенный commit. После этого можно дополнить этот документ результатами VM, сохраняя различие между локальными и VM-проверками.
