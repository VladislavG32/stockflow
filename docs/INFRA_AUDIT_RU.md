# Дополнительный аудит инфраструктуры ЛР4–8

## Найдено и исправлено

| Проблема прежней подготовки | Исправление |
|---|---|
| Обязательный Server/Docker на Windows | Server и сборки на отдельном Linux CI, Windows клиент |
| Reverse tunnel Windows→TEST18111 | Прямой private SERVER_URL; обязательный env вместо скрытого localhost |
| Next/npm/Docker build на TEST4ГБ с рабочей PG | Сборочный агент CI; TEST только готовые образы и лёгкие тесты |
| Перенос тестов на CI нарушил бы требование схемы TEST | Отдельный Acceptance на TEST, schema artifact именно от него |
| Повторная сборка опубликованного образа | docker save/checksum/load одной sameChain, tag/push без rebuild |
| Ограничение только Java агента не ограничивало builds | BuildKit3ГБ, npm2300МБ, RAM/disk preflight на соответствующем узле |
| Builder metadata отсутствовали бы в контейнере агента | Общий /opt/stockflow-ci/buildx, одинаковый BUILDX_CONFIG, создание root |
| Demo secret в /tmp агента не виден Docker хоста | Временная папка под общим PWD/artifacts |
| Нет проверки места под backup/restore на25ГБ | pg_database_size и запас места до создания копий |
| Ошибочный SSH alias мог вести к другому стенду | hostname должен совпадать с TARGET плюс прежняя проверка volume |
| Старый agent_conf мог сохранять18111 | Проверка только serverUrl и адресное обновление без удаления авторизации/тома |
| Расходящиеся ранние инструкции | Linux setup, LAB4–8, архитектура и защита обновлены во всех ready-ветках |

Основной вариант — новая CI Linux VM8ГБ/4CPU/60ГБ в той же Host-Only сети.
Она пока НЕ создана. Существующие TEST/STAGE/PROD не менялись. Домашний сервер
может заменить CI только после подтверждения ОС/Docker/частного маршрута TEST↔CI.
В новой цепочке5 конфигураций с ЛР7: Verify(CI)→Acceptance(TEST)→Publish(CI)→Stage(TEST),
затем ручной Prod(TEST). В ЛР4 только Verify/Publish, с ЛР5 добавляется Stage.

## Что не выполнялось

Подключения к VM, создание VM, установка Docker на VM, Docker build/run/push,
TeamCity build, SSH-доставка, backup и миграции реальных стендов не выполнялись.
Проверенные конфигурации ещё не являются сданными лабораторными. Нужны реальные
ресурсы/сеть/аккаунты, независимый review PR и скриншоты по пошаговым инструкциям.
Старые положительные проверки приложения относятся к предыдущей подготовке;
новые результаты будут указаны отдельно в IMPLEMENTATION_STATUS_RU.

Порядок обновления веток без force описан в BRANCH_UPDATE_RU. SQL0000/0001/0002
не изменяются инфраструктурным исправлением; ручная фаза по-прежнему отдельно от auto.
