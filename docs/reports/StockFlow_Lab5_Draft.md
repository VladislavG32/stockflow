## Функциональное изменение

Добавлен фильтр «Нет в наличии»: он показывает материалы с balance === 0 независимо от минимального запаса. Материал с minimumStock=0 также попадает в выборку. Фильтры дефицита и нормы сохраняют прежний смысл.

Фильтр сочетается с поиском, категорией и сортировкой. Обновлённый интерфейс и навигация сохранены. Патч docs/lab5-ui-compatibility.patch проверен на применимость до применения. Миграции и схема БД не изменены.

## Цепочка доставки

Verify → ручной Publish → ручной Stage. Verify создаёт проверенные образы и архив с частями и SHA-256. Publish получает артефакт той же цепочки, проверяет контрольные суммы и revision и публикует без повторной сборки. Stage получает release.env той же цепочки, сравнивает RELEASE_SHA с checkout и передаёт по SSH отслеживаемые файлы этого snapshot.

Stage разрешён только из dev и назначен stockflow-test-agent. Автоматические триггеры Publish и Stage отключены. Publish, Deploy и рабочие миграции в ходе подготовки не запускались.

## Сохранение PostgreSQL и возврат версии

На STAGE проверяются hostname, существующий Compose project, контейнер db и ожидаемый том PostgreSQL. Используется общая блокировка deploy/rollback. Digest и revision образов проверяются перед обновлением.

Меняется только app командой up -d --no-deps --no-build --pull never app. Проверка /api/ready подтверждает HTTP-ответ и JSON с database=ok, затем сверяются image ID приложения и прежний контейнер/том БД. Сервис migrate не запускается.

При ошибке обновления восстанавливается прежний app image ID с повторной readiness-проверкой. Ошибка rollback возвращает код 2 для вмешательства оператора. После успеха сохраняются current.env и previous.env. Ручной возврат выполняется scripts/ops/rollback-app.sh. Удаление volumes и пересоздание PostgreSQL не входят в доставку.
