## Сохранено и ограничения безопасности

- API-контракты и бизнес-формула не менялись; `drizzle/` и `src/db/schema.ts` без изменений относительно dev. Новые зависимости интерфейса не добавлены, SVG-иконки локальные.
- `.env`, node_modules, сборки, логи, артефакты и временный PostgreSQL исключены Git/Docker context. Публикуемые `.env.example` содержат заполнители. Исходные зависимости имеют реальное применение; кандидатов на удаление вслепую нет.
- Нет аутентификации, ролей, rate limiting и пагинации. Все данные загружаются целиком — подходит небольшому складу; при росте нужны серверные выборки и лимиты. Списание/возвраты и дробные единицы не реализованы.
- Проверка Origin защищает браузерные запросы от чужого сайта, но не заменяет авторизацию: прямой клиент без Origin может писать данные. Доверенная сеть остаётся обязательным ограничением.
- TeamCity build-agent имеет Docker socket/root; запускать только доверенный код. Verify охватывает ветки, Publish имеет секреты только на dev/prod. Не подключать untrusted fork-код к такому агенту.
- Compose/DSL проверяются как конфигурация; фактические firewall, TLS, backup, секреты TeamCity и настройки GitHub branch protection без доступа к среде не подтверждены.
- Более строгая проверка checksum применённых миграций присутствует в будущей подготовке, но не переносилась вместе с ЛР №8 в текущий этап.
